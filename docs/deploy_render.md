# Deploying MANTIS on Render

One web service on Render's **free** plan: the React console and the FastAPI backend in one
container, same origin, built from the repo's `Dockerfile` (Node builds the
console, **Python 3.12** runs the server). Defined in [`render.yaml`](../render.yaml).

## One-time setup (about 3 minutes)

1. Push `main` to GitHub (`ambekararya2005/Paypal-AI-Hackathon-`, public).
2. Render dashboard → **New +** → **Blueprint**.
3. Connect the GitHub repo if asked, select it, branch `main`. Render reads
   `render.yaml` and shows one service, **mantis** (Docker, *Free*, Oregon). No
   card is asked for.
4. Render asks for the four values marked `sync: false`. Paste them from your
   local `.env`:

   | Variable | Value |
   |---|---|
   | `PAYPAL_CLIENT_ID` | the **US** sandbox app's client id |
   | `PAYPAL_CLIENT_SECRET` | its secret |
   | `FASTROUTER_API_KEY` | your FastRouter key |
   | `AG_STUDIO_LICENSE_KEY` | the AG Studio Pro trial key (the value of `VITE_AG_STUDIO_LICENSE_KEY` in `.env`) |

5. **Apply**. The first build takes ~6-8 minutes (npm + scikit-learn wheels).
6. When the deploy is live, the URL is `https://mantis-<suffix>.onrender.com`
   (shown at the top of the service page). Check `/health` and `/api/limits`.

It must stay up until **15 Dec 2026** for judging; the AG Studio trial key is
valid to 24 Dec 2026.

## What the free plan costs you

Nothing is billed, and memory is not the constraint: measured **51 MB idle and 164
MB** after a dashboard load, a playground replay and a Verify, against 512 MB. Two
things are different from a paid instance:

| | Effect for a judge |
|---|---|
| **Sleeps after 15 idle minutes** | the first request after that takes about a minute while the service wakes; everything after is normal speed |
| **No persistent disk** | `MANTIS_RUNTIME_DIR` is the container's own filesystem, reset on every sleep and redeploy |

What survives a reset, because it is in the image: the six seeded sandbox orders
in the dashboard, their receipts and Verify, the recorded playground replays, and
every console screen. What does not: playground runs made since the last wake (log
rows, their receipts, candidate cards), a held order's consent link, and the daily
cap counters. The counters reset only when nobody has used the service for 15
minutes, so a visitor spending the caps keeps them in force; the per-IP limits and
the kill switch do not depend on the disk at all.

**To upgrade** (needs a card on the Render account): in `render.yaml` set
`plan: standard` and add
`disk: {name: mantis-runtime, mountPath: /var/data, sizeGB: 1}`, then push. No
code change.

## Environment variables

Set by `render.yaml` (change them in the dashboard; no redeploy of code needed):

| Variable | Default | What it does |
|---|---|---|
| `MANTIS_PAYPAL_MODE` | `live` | the PayPal **sandbox**. Production is not configurable anywhere. |
| `MANTIS_PUBLIC` | `1` | turns the daily caps on |
| `MANTIS_LIVE_DISABLED` | `0` | **kill switch.** `1` = no live LLM or PayPal call anywhere; the gate runs on mock PayPal and the playground offers recorded attacks |
| `MANTIS_CAP_RUNS` | `100` | playground agent runs per UTC day |
| `MANTIS_CAP_LLM` | `2500` (built-in) | live LLM calls per UTC day |
| `MANTIS_CAP_PAYPAL` | `1500` (built-in) | PayPal sandbox calls per UTC day |
| `MANTIS_RATE_PER_MIN` | `60` | API writes (POST) per IP per minute; reads (GET) are capped at 300 |
| `MANTIS_RUNTIME_DIR` | `/var/data` | gate log, receipts, quota counters, playground candidates (container filesystem on free; a persistent disk on paid) |
| `MANTIS_WARM` | `1` | fits the gate's and the playground's scorers in a background thread at startup, so the first visitor after a wake does not wait 15-30 s for them |
| `MANTIS_STORE_VARIANT` | `poisoned` | the demo store variant the MCP proxy serves |
| `LLM_PROVIDER`, `FASTROUTER_BASE_URL`, `LLM_MODEL_*` | FastRouter, gpt-4.1-mini agent, Claude Sonnet 4.6 judge and compiler | |
| `MANTIS_MANDATE_KEY` | generated by Render | HMAC key for mandate signatures |

Secrets (`sync: false`) live only in Render's environment. The Docker build never
sees `.env`: it is in `.dockerignore`, and the image copies named paths only.

## Operating it

- **Pull the plug:** set `MANTIS_LIVE_DISABLED=1` and save (Render restarts the
  service, about 30 s). Everything still works on recorded runs.
- **See the spend:** `GET /api/limits` returns today's counters, caps and the
  kill-switch state.
- **Abuse guards:** 60 API writes and 300 reads per IP per minute, 5 playground runs per IP
  per hour, request bodies over 32 KB refused, playground pages capped at 1,500
  characters, and the daily caps above.

## Why no Render Workflow

The obvious candidate was a scheduled job that re-verifies receipts against
PayPal. Receipts live on this service's own filesystem (or, on a paid plan, its
persistent disk, which Render attaches to one service only), so a separate
scheduled workflow could not read them. Receipt verification is on demand instead (`GET /api/receipts/{order_id}/verify`,
the **Verify** button in MANTIS Ops).
